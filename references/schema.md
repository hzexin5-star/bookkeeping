# 账本字段与约定

## 表结构

账本是 UTF-8（带 BOM）CSV，首行为表头，列顺序固定：

| 列 | 含义 | 取值约定 |
| --- | --- | --- |
| `id` | 记录编号 | 由脚本自增生成，唯一，用于 `update` / `delete` |
| `date` | 发生日期 | `YYYY-MM-DD`；脚本也接受 `YYYY/MM/DD`、`YYYYMMDD`、`MM-DD` 并归一化 |
| `type` | 收支方向 | `income`（收入）或 `expense`（支出） |
| `category` | 分类 | 自由文本，见下方“分类命名” |
| `amount` | 金额 | 正数，纯数字，不带货币符号；方向由 `type` 决定 |
| `account` | 账户 | 例如 现金 / 微信 / 支付宝 / 银行卡；可为空 |
| `note` | 备注 | 自由文本；可为空 |

示例：

```csv
id,date,type,category,amount,account,note
1,2026-10-01,income,工资,12000,银行卡,
2,2026-10-07,expense,餐饮,35.5,微信,午饭
```

## 分类命名

分类沿用用户原话，保持稳定：

- 同一类支出用同一个词。用户第一次说“打车”，之后说“出租车”时，沿用用户当前说法即可，但**不要**把“餐饮”和“买菜”这类语义不同的项擅自合并。
- 用户没给分类时脚本记为 `未分类`；能在不臆造的前提下从备注判断（例如备注“午饭”），可以主动建议一个分类，但要在回复中说明。
- 只有在用户明确要求时，才做分类合并/重命名；批量改动用 `update` 逐条处理。

## 金额与币种

- `amount` 一律正数，去掉 `¥`、千分位逗号后写入。
- 默认币种为人民币元。出现其他币种（美元、日元等）时，在报表中标注币种；不同币种不要直接相加，需要换算时先向用户确认汇率。

## 统计口径

- `income` 合计为总收入，`expense` 合计为总支出，二者之差为净结余。
- 分类占比 = 该分类金额 ÷ 同类型（收入或支出）合计。
- `balance` 按账户累计：每个账户的收入减支出，即该账户净结余，不是真实银行余额。
- 时间区间用 `--month YYYY-MM` 或 `--from` / `--to`（含端点）限定；两者可同时作为筛选条件。

## 手工修改的边界

- 追加、修改、删除一律通过 `scripts/ledger.py`，避免破坏列顺序和编码。
- 若确需在 Excel 里编辑，保存为 UTF-8 CSV，并保证表头列名不变；编辑后先用 `list` 校验一遍。
